Upstream submission means offering the change to [this repository](https://github.com/parth-6-5-4/knull). It does not guarantee acceptance or merging, grant repository write access, or transfer copyright. If upstream submission is unavailable, the license provides a public-fork/attempted-notice route. Unrelated software communicating through an API is not automatically covered.

This is **source-available**, not an OSI-approved open-source license. Standard open-source terms permit business use; adding a commercial ban is a different policy. [OSI definition, section 6](https://opensource.org/osd).

Research compared [GNU license guidance](https://www.gnu.org/licenses/gpl-faq.html) and [PolyForm Noncommercial 1.0.0](https://polyformproject.org/licenses/noncommercial/1.0.0). PolyForm provides a standard noncommercial option but does not itself require upstream submission. The custom text combines the maintainer's selected noncommercial and source-submission conditions; it must not be described as unmodified GPL, AGPL, PolyForm or MIT. Custom legal wording merits legal review; no claim of guaranteed enforceability is made here.

Previously published versions through `f4f541332b3f78a755bccc5f4890931b1b256d07` were offered under MIT. The [prior MIT notice](../LICENSES/MIT-legacy.txt) is retained. This change does not revoke previously granted rights or erase notices owed for material obtained under earlier terms. New modifications are not additionally offered under MIT merely because that historical notice is present. Third-party dependencies/assets retain their own licenses.

The license change is committed before the newly published implementation changes, so those changes are not first released in an intermediate MIT-labeled commit. A branch push applies these terms on that branch; merging to the default branch is a separate operation.
