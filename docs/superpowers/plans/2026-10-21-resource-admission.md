**Goal:** Govern every current Hive model call with conserved token reservations, shared local-process capacity and bounded fair queues, integrated through API, CLI and direct execution.

**Architecture:** Keep one SQLite v2 authority for existing Hive state plus resource policy, allocations, calls and admission. ## Global Constraints

- One trusted local host; shared canonical Hive SQLite file and persisted policy identity. Separate databases are separate deployments. No network filesystem/multi-host guarantee.
- Every Hive planner/researcher/verifier/writer call uses governed completion. Legacy LangGraph remains outside these ceilings and keeps its existing interface.
- Active runs / queued runs: **4 / 20**. Active provider calls: **global 8; per run 3; per provider 2**. Pending calls: **global 128; per run 16**. Existing workers: **1–8 per active run**.
- Default run token allowance **200,000**; inherited grants partition it. Counts and aggregate arithmetic use checked signed 64-bit integers, never floats or bools.
- Queue wait: **at most 60 seconds and remaining run/task deadline**. Local call duration: **at most 120 seconds and remaining run/task deadline**. Existing run/task defaults: **1,800 / 600 seconds**. Run queue wait consumes the run deadline.
- Run ownership: heartbeat **3 seconds**, lease **15 seconds**. Waiter freshness: expiry **5 seconds**, refresh **at most 1 second**. No persisted monotonic timestamp crosses process/loop epochs.
- Existing task `max_attempts` default **3**. Runner alone owns bounded transport/task retries; governed dispatcher/router/SDK retries are **zero**. Planner gets one attempt. Queue/configuration failures are not transport retries.
- `budget_mode` defaults to **hard** in API/MCP/CLI/direct calls. Unknown hard profile denies before dispatch. Estimated mode requires explicit selection and remains labelled soft.
- No token hold/call permit while merely queued. Reserve allowance plus every needed permit atomically; commit dispatch intent before send. Task/run ownership expiry never releases uncertain external work.
- Execution-terminal evidence releases capacity; complete usage releases/replaces token holds. These are independent. Missing receipt categories are unknown, not zero. No invented quarantine duration or automatic unfreeze after overrun.
- Explicit stopped-writer schema v2 maintenance with verified private backup; old writers refuse v2. No silent startup upgrade, real application DB migration, paid call, broad dependency repair or personal host setup during implementation.
- POST keeps **202**, existing `run_id` and **status running**, plus additive admission state. Queue-full: **429**, Retry-After, `resource_queue_full`; temporary admission-store busy: **503**; unqualified hard profile/config: **422**. No automatic POST replay.
- HIVE-003 snapshot, literal rendering, lease and task/run-deadline publication guarantees remain required. Historical report bytes and measured usage remain unchanged.
- Intermediate tasks do not close HIVE-004-A. All integrated acceptance gates, including local load/fault and provider controls, must pass; cross-host and monetary parent requirements remain incomplete.

Use frozen dataclasses or equivalently immutable validated records in `resource_types.py`. The following field names are the shared task contract; later tasks must not invent alternate spellings:

- `Clock.utc() -> float`, `Clock.monotonic() -> float`, `await Clock.sleep(seconds)` define the injected clock seam. Production uses time.time/time.monotonic/asyncio.sleep; SQLiteTransactions receives the same clock. Asyncio timeout_at uses loop.time conversion, never a persisted or system-monotonic absolute timestamp.
- `ResourcePolicy(active_runs=4, queued_runs=20, global_calls=8, run_calls=3, provider_calls=2, queued_calls=128, run_queued_calls=16, queue_wait_s=60, call_timeout_s=120, owner_heartbeat_s=3, owner_lease_s=15, waiter_refresh_s=1, waiter_lease_s=5, busy_timeout_ms=50, cleanup_timeout_s=5, clock_skew_s=2)`. Last three are implementation choices for finite local I/O/cleanup and detecting clock discontinuity; they do not extend dispatch deadlines. Strictly validate finite values/relationships and canonicalize to a policy digest.
- `RunRequest(objective, workers, max_subtasks, budget_tokens, task_timeout_s, run_timeout_s, budget_mode, max_attempts, lease_s, heartbeat_s, tick_s)` retains current runner defaults; serializable replay is explicit. Runtime search callables are held by origin process, never serialized.
- `RunTicket(run_id, allocation_id, accepted_at_utc, expires_at_utc, policy_digest, profile_digest, budget_mode)`; `RunAuthority(run_id, owner_id, fence)`.
- `CallAuthority(run: RunAuthority, allocation_id, role, task_id, task_owner, task_attempt, task_fence, ordinal)`. Planner uses null task fields and a run-scoped ordinal; task calls bind existing assignment identity. Task/run monotonic deadlines are local method arguments, not persisted fields.
- `PreparedCall(call_id, authority, provider, model, endpoint_id, profile_digest, sdk_version, request_fingerprint, messages, temperature, max_output_tokens, bound_tokens, budget_mode, expires_at_utc)`. Messages remain in originating coroutine; only metadata/fingerprint is persisted. `call_id` hashes authority + ordinal, independently of the request fingerprint; changed request/profile reuse at the same logical call position must conflict rather than allocate a second ID. Task retry/fence produces a different ID.
- `UsageReceipt(receipt_id, receipt_digest, provider, requested_model, resolved_model, request_id, input_tokens, output_tokens, total_tokens, categories, usage_complete, execution_terminal)`. Missing counts are null. Task4 normalized `categories` uses disjoint/subsets count maps; Task1 provides only defensive immutable JSON containment. Never sum cached/thought subsets twice. Complete total is authoritative. A normalized partial receipt has no invented zero total.
- `CallOutcome(text, receipt)` for a completed adapter response. `ProviderCallError(LLMError)` carrying `(code, retryable, sent, execution_terminal, receipt=None)` for failures; only proven pre-send error has `sent=False`.
- `CallRecord(call_id, state, bound_tokens, actual_tokens, permits_held, usage_complete, execution_terminal, request_fingerprint)`; `AllocationSnapshot(allocation_id, limit_tokens, used_tokens, available_tokens, debt_tokens, closed, frozen)`.
- `ResourceInspection(accounting_kind, budget_mode, hard_tokens, actual_tokens, reserved_tokens, unknown_tokens, available_tokens, debt_tokens, frozen, queue, occupancy)`. Actual aggregates only complete normalized totals. Partial known counts/lower bounds remain on call receipt metadata; unknown admission charge stays max(original bound, known lower bound), never their sum. `accounting_kind` is `governed-v1` or `historical-measured`. hard_tokens is bool (qualified hard=True, estimated=False); historical budget_mode/hard_tokens/available_tokens may be null when no governed policy exists.
- `ResourceError(code)` subclasses: `ResourceInputError`, `ResourceConflict`, `ResourceDenied`, `ResourceQueueFull`, `ResourceBusy`, `ResourceProfileError`, `ResourcePersistenceError`. Admission/profile/queue failures do not inherit LLMError; runner classifies explicit codes before generic RuntimeError retry rules.

The only product-facing facade is `AdmissionService`. Resource/admission store methods are internal concrete interfaces, not public user tools or a new plugin framework. One HiveStore owns its SQLite connection, transaction coordinator and resource-store accessors; all resource writes share its database. No second accounting file or caller-visible SQL connection is introduced. Execution contract: HiveStore.transactions and HiveStore.database_io share its connection/lock/injected clock; async HiveStore.aclose drains owned work before closing. Unused executor construction creates no thread.

## Review Focus

1. Cancellation while blocking SQLite work is still in a thread: a cancelled coroutine must not authorize a later dispatch or lose an eventual committed reservation. Pin `test_cancel_during_admission_lock_wait_has_no_send` in Task 5 and executor drain in Task 6.
2. Same call ID replay with different profile/credential-independent request, or retries hidden by redirects: incompatible reuse must conflict and one logical attempt must have one transport send. Pin request mutation in Task 2 and redirect/429 counting in Task 4.
3. Terminal response with incomplete usage: release capacity while retaining conservative token hold; neither complete response text nor run cancellation proves zero spend. Pin `test_terminal_partial_receipt_releases_only_capacity` in Tasks 2/5.
4. Different monotonic clock epochs or wall-clock adjustment while queued: original accepted expiry survives handoff; discontinuity fails closed. Pin offset-loop, queue-consumed deadline and clock-jump tests in Tasks 3/6.
5. Existing populated schema/legacy output accidentally rewritten by initialization or once-per-call usage projection: preserve historical bytes and reject mixed writers. Pin migration interruption/old-code rejection in Task 1 and historical readback/projection replay in Task 7.
